# 域（班级 / 课程 / 队伍）

一个域是一个班级、一门课程或一支队伍的空间，有自己的成员和角色、题目、作业、训练、比赛、
公告和成绩。做法仿照 Hydro 的 Domain。代码在 `web/app/libs/uoj-domain-lib.php`、
`uoj-homework-lib.php`、`uoj-training-lib.php` 和 `web/app/controllers/domain/`，
权限规则和其他规则一样都在 `can()` 里。

## 谁能看到、谁能管理

域只对里面的人存在。没有“公开的域”，也没有域的公开介绍页。

| 谁 | 能看到 | 能做什么 |
|---|---|---|
| 系统管理员、OJ 管理员 | 所有域（`/domains` 页有“全部域”列表和搜索） | 管理所有域，等同所有者；不需要成为成员 |
| 域的所有者（创建者） | 自己的域 | 一切，包括任免管理员、转让、归档 |
| 域管理员（所有者任命） | 所在的域 | 设置、成员、邀请，以及教师能做的一切；不能任免管理员、转让、归档 |
| 教师 | 所在的域 | 题目、作业、训练、比赛、公告、成绩 |
| 助教 | 所在的域 | 查看成绩、查看域内所有提交和源码 |
| 学生 | 所在的域 | 做作业、训练、比赛 |
| 其他人（包括别的域的教师） | 看不到 | 打开域里的任何地址都是 404，和域不存在时一样；未登录则跳到登录页 |

说明：

- 所有者只有一个，记在 `domains.owner_username`，不在成员表里；只能通过“转让”变更，
  转让后原所有者成为管理员。
- 谁能创建域由系统管理员的一个开关决定（系统管理 → 站点设置 →“允许所有登录用户创建域”）：
  - 关（默认）：系统管理员、OJ 管理员、全站角色“教师”和“可创建域”（`domain_creator`，
    给学生队长这类不需要其他教师权限的人）。
  - 开：任何登录用户。创建者就是该域的所有者，可以在自己的域里新建题目、上传数据、
    布置作业和举办比赛；全站的题库、比赛和别人的域不受影响。再关掉后，已创建的域仍归原主。
- 域内的题目、比赛、提交不出现在全站的题库、比赛列表和提交记录里；个人主页的通过题目
  列表和全站通过数也不包含域内的题。
- 归档的域只读，在“我的域”里排到最后，所有者（或全站管理员）可以恢复。域不能删除。

## 进入一个域

1. **管理者添加**：成员页按用户名添加，同时指定角色。
2. **导入名单**：每行一个用户名或学号。学号对应的学生还没登录过（没有账号）时会挂起，
   他第一次通过统一身份认证登录时自动成为成员。
3. **邀请链接**：成员页生成，可设有效期和使用次数，只能以学生身份加入。链接只在生成时
   显示一次，数据库里只存哈希；链接形如 `/domains/join#<令牌>`，令牌不会进访问日志。
   入口页不透露域是否存在，失败一律提示“无效或已过期”。

通过邀请进来的人可以自己退出；被添加或导入名单的人（班级的学生）只能由管理者移除。

## 题目

- **新建**：域内题目只对成员可见，由域的教师管理，不需要逐题设置管理者。
- **从题库复制**：得到一道完全独立的域内题（题面、数据、配置都复制，占独立的磁盘空间），
  之后两边互不影响。能复制的是全站公开题，或你任教的域里的题。
- 自定义 judger 的批准不随复制继承：系统管理员同步过的内容按哈希登记，复制出的题只有
  内容与登记过的完全一致才能由教师同步，否则仍需系统管理员同步。

## 作业

生命周期：草稿 → 发布（冻结题目）→ 未开始 → 进行中 → 迟交期 → 已截止。

- **认领**：学生要点“认领”才算参加。教师可以在管理页看到未认领的学生、手动添加、
  或一键把未认领的全部加入；导出成绩时可以选择包含未认领的学生。
- **迟交规则由布置者设置**：每个作业单独设“从何时起算迟交”和若干分段，例如
  “迟交 0 小时起按 80%，1 天起按 50%”。单位可选小时或天，最多 20 段；段内系数不变。
  截止时间之后的提交不计入正式成绩。
- **每题成绩**：取“得分 × 系数”最高的一次提交，相同时取较早的。
- **发布即冻结题目**：作业用到的全站公开题在发布时复制成域内的隐藏题，作业只引用副本
  （同一个域里同一道题的同一版本只复制一次）。之后别人修改公开题不影响作业。
  发布后题目列表不能再改；开始之前可以撤回发布再改。
- **结算**：截止时生成一份不可变的正式成绩快照，记录每个成绩来自哪次提交、哪个数据
  版本，以及当时的时间和计分规则。之后的提交只影响“订正进度”，不改正式成绩。
  截止前交的提交还没评完时会等待，最多等 `homework.settle-grace` 秒（默认 1800），
  超时就用已有结果结算，并提示有多少份提交没算进去。
- **截止后改了数据怎么办**：管理页会提示哪些题的数据在评测之后有改动。教师填写原因 →
  重测本作业的提交 → 生成候选快照并列出与当前正式成绩的差异 → 确认后才生效，旧快照保留。
- **可见性**：作业内的提交只有本人和工作人员能看到；作业进行中，副本的来源公开题对
  该作业的参与者关闭他人源码（挡不住小号，仅防君子）。
- 还有：指定某个成员为单个作业的维护者、克隆作业、导出 CSV（含学号和姓名）。

## 训练

按顺序排好的题单，可以放本域的题和全站公开题（直接引用，不复制）。不用认领，没有截止，
不冻结成绩：看的是每题的最好成绩，不论在哪里交的。学生看到自己的进度，助教以上能看到
每个学生的完成情况并导出。必做题全部通过即算完成。

## 比赛、公告、成绩

- **比赛**：在域里创建，只对成员可见，由域的教师管理，页面和全站比赛相同；和其他非管理员创建的比赛一样默认不计 Rating。
- **公告**：Markdown，可置顶。
- **成绩**（助教以上）：学生 × 作业的总表。已结算的作业显示正式成绩并计入合计，未结算的
  显示当前成绩（斜体）不计入合计，未认领的留空。可导出 CSV。
- 概览页会给教师列出“待处理”：未认领人数、待确认的重新结算、数据有改动的题、发布失败。

## 部署与升级

- 容器启动脚本每分钟执行一次 `php /opt/uoj/web/app/cli.php homework:tick`，负责推进发布和结算。
  页面访问也会推进当前作业，所以定时任务偶尔不跑不会出错，只是没人看的作业会晚一点结算。
  不用容器部署时请自己加一条每分钟的 cron。
- 配置项：`homework.settle-grace`（秒）。
- 升级会执行 `1009`–`1012` 四个迁移。`1010` 会给 `submissions` 加两列和一个索引，
  提交很多时需要维护窗口。
- 提交时间（`submit_time`）现在取 Web 服务器的时钟而不是数据库的，两者应保持同步。
- 评测协议没有变化，评测机不需要升级。

## 没有做的

评测机按作业固定的旧数据版本评测（现在靠“发布时复制”来冻结）、题面版本化、域内分组、
自定义角色、训练的前置关系、作业附件、截止提醒、邮件通知、数据去重存储、
从学校课程系统自动同步名单。
