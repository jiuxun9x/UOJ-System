# 角色与权限

所有权限判断都在 `web/app/libs/uoj-permission-lib.php` 的 `can($user, $ability, $resource)` 里，
规则有不依赖数据库的单元测试（`web/tests/permission_test.php`）。

## 角色

全站角色：

| 角色 | 怎么设置 | 能做什么 |
|---|---|---|
| 系统管理员 | `user_info.usergroup = 'S'`（和原版的超级用户是同一回事，第一个注册的用户自动获得） | 一切，包括授予角色、修改用户名、管理评测机、批准自定义 judger、查看审计日志 |
| OJ 管理员 | 系统管理 → 用户操作 → 授予角色 | 管理所有题目、比赛、提交、博客，封禁普通用户；不能改角色、不能管评测机、不能批准自定义 judger |
| 教师 | 同上 | 新建题目和比赛（自动成为其管理者/负责人），查看学生的学号和姓名 |
| 学生 | 没有任何角色的用户 | |

单个资源上的角色：

| 角色 | 怎么设置 | 能做什么 |
|---|---|---|
| 题目管理者 | 题目管理 → 管理者 | 编辑题面、数据、可见性，重测，查看该题所有提交 |
| 比赛负责人 | 比赛管理 → 管理者，`+用户名 [owner]` | 修改比赛时间、赛制、试题、人员，发公告，开始最终测试，公布成绩 |
| 比赛助理 | 比赛管理 → 管理者，`+用户名` | 进入后台、查看比赛内所有提交、回答提问、导出排名 |

说明：

- 比赛负责人不需要任何全站角色。升级前已经在比赛“管理者”名单里的人成为助理，权限和以前一样。
- 非管理员创建的比赛默认不计入 Rating，只有管理员能改。
- 往比赛里加题仍然要求操作者是该题的管理者。
- 不能取消最后一位系统管理员；OJ 管理员不能封禁或修改管理员；被封禁的用户会失去所有角色。
- 课程里的教师和助教（按班级/课程划分的权限）在第四阶段随课程一起加入。

## 提交记录谁能看

平时不变：所有人都能看别人的提交和源码，不论自己是否通过；题目管理者可以在“数据 → 提交记录可视权限”里按题收紧。

比赛进行中：

- 在比赛里交的提交，只有本人和工作人员能看到（列表里也不出现）。
- 这场比赛用到的题，**所有**提交的源码和测试点详情都对其他人关闭，包括比赛开始前交的。
- 只有工作人员能 hack 这些题的提交。

比赛结束后恢复平时的规则。“工作人员”指管理员、该题的管理者、该比赛的负责人和助理；
他们和提交者本人始终能看到提交的全部内容，不受题目可见性设置影响。

作业（Training）的“进行中关闭”规则在第四阶段加入，用的是同一个判断入口。

## 审计日志

系统管理 → 审计日志（仅系统管理员）。记录角色和封禁的变更、改用户名、统一身份认证建号和绑定、
题目的新建/题面/管理者/数据上传/配置（时限、空间限制）/同步/重测、比赛的新建/设置/人员/试题/
最终测试/公布成绩/导出排名、提交和 hack 的重测与删除、评测机的增删和启停。

## 部署在反向代理后面

`X-Forwarded-Host`、`X-Forwarded-Proto`、`X-Forwarded-For` 只在请求来自 `web.trusted-proxies`
里列出的地址时才被采信：

```php
'web' => [
	'trusted-proxies' => ['172.18.0.0/16'],   // 反向代理的地址或网段
	...
],
```

如果反向代理没有把原始的 `Host` 头传给 UOJ，必须配置这一项，否则页面里的链接会指向内部地址。
站点使用 https 时请把 `web.main.protocol` 设为 `https`，这样 Cookie 会带上 `Secure`。
生产环境建议把 `web.main.host` 写成固定的域名，而不是从请求里取。
